## 1. DATA MODEL

### Table: `user_saves_v2` (extends existing `wa_saves`)

```sql
CREATE TABLE user_saves_v2 (
  id BIGINT PRIMARY KEY,
  user_phone TEXT NOT NULL,
  
  -- Content
  title TEXT NOT NULL,
  description TEXT,
  url TEXT,
  category TEXT,  -- "dining", "service", "event", "place", "receipt", etc.
  source TEXT,    -- "brief", "whatsapp", "web", "email", "calendar"
  
  -- Location context
  location TEXT,  -- Address or postcode
  lat FLOAT, lng FLOAT,  -- Coordinates if available
  
  -- Metadata
  created_at TIMESTAMP,
  last_surfaced_at TIMESTAMP,  -- When proactive mention last happened
  user_tags TEXT[],  -- User-added tags (JSON array or comma-sep)
  ai_tags TEXT[],    -- Auto-generated by Groov/LLM
  
  -- User feedback loop
  user_notes TEXT,   -- Annotation ("Good vegan options")
  relevance_score FLOAT DEFAULT 0.5,  -- Updated by pattern detection
  visit_count INT DEFAULT 0,  -- How many times user acted on this save
  
  -- Status
  archived BOOLEAN DEFAULT false,
  deleted BOOLEAN DEFAULT false
);
```

### Table: `save_interactions` (for pattern detection)

```sql
CREATE TABLE save_interactions (
  id BIGINT PRIMARY KEY,
  save_id BIGINT REFERENCES user_saves_v2(id),
  user_phone TEXT,
  
  event_type TEXT,  -- "surfaced", "clicked", "visited", "feedback"
  context TEXT,     -- JSON with brief_id, location, day_of_week, etc.
  timestamp TIMESTAMP,
  
  -- For surfacing: did user act on it?
  action_taken BOOLEAN,  -- User clicked/visited after surfacing
  latency_mins INT       -- Minutes between surfacing and action
);
```

## 3. FLOW 2: PROACTIVE SURFACING (Context Trigger)

### 3.1 Logic (Runs in brief generation)

**When building brief:**

```python
def _add_proactive_mentions(ctx, from_number, home_postcode):
  """
  Check user's saves; surface if contextually relevant.
  """
  user_saves = db.query("user_saves_v2").where(
    phone=from_number, 
    archived=False
  )
  
  for save in user_saves:
    # Only surface dining/services (high engagement)
    if save.category not in ["dining", "service", "place"]:
      continue
    
    # Calculate relevance
    dist_km = haversine(home_postcode, save.location)
    
    # Surface if:
    # - Within 5km AND
    # - User hasn't seen this in past 7 days AND
    # - Relevance score > 0.4
    if dist_km < 5 and not _recently_surfaced(save.id, 7) and save.relevance_score > 0.4:
      ctx["proactive_mentions"] = ctx.get("proactive_mentions", []) + [{
        "save_id": save.id,
        "title": save.title,
        "distance_km": dist_km,
        "category": save.category,
        "open_now": _check_hours(save),  # If have phone/hours
      }]
      
      # Log surfacing for pattern tracking
      db.insert("save_interactions", {
        "save_id": save.id,
        "event_type": "surfaced",
        "context": json({"brief_id": ctx.id, "distance_km": dist_km}),
        "timestamp": now()
      })
  
  return ctx
```

## 6. FLOW 5: PATTERN DETECTION & PERSONALIZATION

### 6.1 Background Job (Daily)

```python
def _daily_pattern_analysis(user_phone):
  """
  Analyze user save/retrieval patterns.
  Update relevance_score for smarter surfacing.
  """
  
  # Last 30 days of saves
  saves = db.query("user_saves_v2").where(
    phone=user_phone,
    created_at >= now() - 30.days
  )
  
  # Categorize by type
  by_category = group_by(saves, "category")
  
  # Calculate engagement metrics
  for category, items in by_category.items():
    # Interaction data
    interactions = db.query("save_interactions").where(
      save_id IN (item.id for item in items),
      event_type IN ["clicked", "visited"]
    )
    
    engagement_rate = len(interactions) / len(items)
    
    # Update base relevance for category
    for item in items:
      if engagement_rate > 0.5:
        item.relevance_score = 0.8  # High engagement
      elif engagement_rate > 0.2:
        item.relevance_score = 0.5  # Medium
      else:
        item.relevance_score = 0.2  # Low
      
      item.save()
  
  # Detect patterns
  patterns = {
    "high_save_categories": [cat for cat, items in by_category.items() 
                              if len(items) > 3],
    "save_frequency": len(saves) / 30,  # Per day
    "optimal_surfacing_time": _detect_time_pattern(interactions),
  }
  
  # Store patterns
  db.insert("user_patterns", {
    "user_phone": user_phone,
    "patterns": json(patterns),
    "last_updated": now()
  })
  
  return patterns
```

### 6.2 Use Patterns in Brief

```python
user_patterns = db.query("user_patterns").where(phone=from_number)

# Only surface categories user engages with
if user_patterns.high_save_categories:
  proactive_filter = lambda save: save.category in user_patterns.high_save_categories
else:
  proactive_filter = lambda save: True  # Default: show all

# Time-based surfacing (if user engages more at certain times)
if user_patterns.optimal_surfacing_time:
  current_hour = now().hour
  if current_hour not in user_patterns.optimal_surfacing_time:
    skip_surfacing = True  # Don't distract user
```

## 8. OPEN QUESTIONS

1. **Save everything or curate?**
   - Should every place/event in brief auto-suggest save? Or only user-triggered?
   - → Recommended: User-triggered (button) to avoid spam

2. **Proactive distance threshold?**
   - How far is "nearby"? (1 mile? 5 miles? User-configurable?)
   - → Start with 5 miles; make configurable later

3. **Web dashboard hosting?**
   - New route on miru.humanagency.co? Or separate site?
   - → Add to miru.humanagency.co/saves (authenticated)

4. **Annotation friction?**
   - Require user notes immediately, or optional/later?
   - → Optional on save; encourage on web dashboard

5. **Archive vs. Delete?**
   - Should users be able to permanently delete or only archive?
   - → Archive by default (reversible); permanent delete after 30 days?

6. **Export?**
   - Should users export their saves (PDF, CSV)?
   - → Phase 2+; not MVP

7. **Sharing?**
   - Can users share a save with someone (e.g., "Try this restaurant")?
   - → Phase 2+; focus on personal retrieval first
